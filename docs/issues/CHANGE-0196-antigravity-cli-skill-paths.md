# Keep AAI skills on the Antigravity CLI project path

## Summary
- Antigravity CLI reads project skills from `.agents/skills/{skill_name}/SKILL.md`. That directory is already the in-repo mirror of `.claude/skills`.
- The global and shared paths in the CLI lookup table are not install targets. This repository does not copy skills into `~/.gemini/antigravity-cli/skills/` or `~/.gemini/skills/`.

## Motivation / Business Value
- Other agents see AAI skills in the project directory their harness reads. Antigravity CLI's project directory is `.agents/skills/{skill_name}/SKILL.md`, which `sync-harness-skills.mjs` already maintains.
- Publishing the same files into a user's home directory would install skills outside the project. The owner rejected that.

## Scope
- In scope:
  - Keep `.claude/skills/{skill_name}/SKILL.md` as the only hand-authored source.
  - Keep the existing project mirror `.agents/skills/{skill_name}/SKILL.md`, generated by `sync-harness-skills.mjs` from `.aai/system/HARNESS_SKILLS.yaml` (`.agents/skills|carry|no`).
  - A regression that this mirror still matches the source and that no script publishes into the CLI's home lookup paths.
- Out of scope:
  - Copying or installing skills into `~/.gemini/antigravity-cli/skills/`, `~/.gemini/skills/`, or any other per-user home directory.
  - `publish-home-skills.mjs` and any `--home` publisher.
  - Editing skill bodies, names, or descriptions.
  - Adding `.cursor/skills/` (refused by `HARNESS_SKILLS.yaml` D2).
  - Changing the committed Gemini CLI project mirror at `.gemini/skills/` (that tree is inside the repo; it is not `$HOME`).
  - Reopening the mutation-clone intake or the four merged Windows pull requests.

## Affected Area
- Project mirror already shipped: `.agents/skills/` (parity with `.claude/skills/`), declared in `.aai/system/HARNESS_SKILLS.yaml` and generated by `.aai/scripts/sync-harness-skills.mjs`.
- `REQUIRED_MIRROR_TREES` stays `.agents/skills`, `.codex/skills`, `.gemini/skills`. None of those paths is under a user home.

## Desired Behavior (To-Be)
- After `node .aai/scripts/sync-harness-skills.mjs --check`, every source skill exists at `.agents/skills/{skill_name}/SKILL.md` and matches the source bytes (this tree carries `model:`).
- No command in this repository creates `~/.gemini/antigravity-cli/skills/` or writes skills into `~/.gemini/skills/`.

## Acceptance Criteria
- AC-001: `node .aai/scripts/sync-harness-skills.mjs --check` exits 0, and `.agents/skills/{skill_name}/SKILL.md` is byte-identical to the matching source skill.
- AC-002: `publish-home-skills.mjs` is absent, `.aai/system/PROFILES.yaml` does not list it, and no script under `.aai/scripts` names `antigravity-cli`.

## Verification
- `node .aai/scripts/sync-harness-skills.mjs --check` exits 0.
- `bash .aai/scripts/aai-run-tests.sh bash tests/skills/test-aai-antigravity-project-skills.sh` exits 0.

## Constraints / Risks
- Official Antigravity CLI migration table (https://antigravity.google/docs/cli/gcli-migration/, read 2026-09-29) lists three lookup locations: workspace `.agents/skills/`, Antigravity global `~/.gemini/antigravity-cli/skills/`, and Gemini CLI shared `~/.gemini/skills/`. The owner correction is that the global and shared rows are the CLI's own lookup table, not a request to publish this repo's skills into `$HOME`.
- The in-repo `.gemini/skills` mirror is a different path from `~/.gemini/skills`. Do not collapse them.
- `HARNESS_SKILLS.yaml` D2 still forbids a `.cursor/skills/` copy.
- No secret is referenced.

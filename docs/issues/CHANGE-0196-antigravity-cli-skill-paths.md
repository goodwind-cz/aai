# Make AAI skills visible on the Antigravity CLI skill paths

## Summary
- Publish the universal AAI skill set so the Antigravity CLI can load it from the three locations it documents, using the same `{skill_name}/SKILL.md` layout AAI already authors.
- The project workspace path is already generated. The two user-home paths are not.

## Motivation / Business Value
- Antigravity CLI (`agy`) does not read `.claude/skills/`. Its migration guide names a workspace path and a global path, and keeps the Gemini CLI shared home path beside them.
- AAI already mirrors 40 skills into `.agents/skills/{skill_name}/SKILL.md`, which is the workspace path. Nothing in this repository installs that same set into `~/.gemini/antigravity-cli/skills/` or `~/.gemini/skills/`.
- An operator who launches `agy` outside this checkout, or who expects global and shared skills, therefore does not see the AAI skills.

## Scope
- In scope:
  - Keep `.claude/skills/{skill_name}/SKILL.md` as the only hand-authored source.
  - Keep the existing project mirror `.agents/skills/{skill_name}/SKILL.md` as the Antigravity CLI workspace surface, still generated by `sync-harness-skills.mjs` from `.aai/system/HARNESS_SKILLS.yaml`.
  - Add one publisher that, given a home directory, writes the same skill set to both home trees below. Tests must pass a fixture home and must not write the real user home.
  - Global (Antigravity CLI): `{home}/.gemini/antigravity-cli/skills/{skill_name}/SKILL.md`.
  - Shared (Gemini CLI global shared path, named Shared in the request): `{home}/.gemini/skills/{skill_name}/SKILL.md`.
  - Idempotent re-run: a second publish leaves the fixture trees matching the source and does not create extra files.
  - A regression check that the existing `.codex/skills` and project `.gemini/skills` mirrors still pass `node .aai/scripts/sync-harness-skills.mjs --check`.
- Out of scope:
  - Implementing this intake.
  - Reopening the mutation-clone intake or the four merged Windows pull requests.
  - Editing skill bodies, names, or descriptions.
  - Adding `.cursor/skills/` (refused by `HARNESS_SKILLS.yaml` D2).
  - Committing either home tree into the git repository. Home paths are install targets.
  - Antigravity IDE or Antigravity 2.0 plugin marketplace layout (`~/.gemini/config/plugins/`, `.agents/plugins/`).
  - Changing which tree carries the frontmatter `model:` key.

## Affected Area
- Project mirror already shipped: `.agents/skills/` (40 `SKILL.md` files, parity with `.claude/skills/` on this checkout), declared in `.aai/system/HARNESS_SKILLS.yaml` as `.agents/skills|carry|no` and generated by `.aai/scripts/sync-harness-skills.mjs`.
- Missing install targets: `~/.gemini/antigravity-cli/skills/` and `~/.gemini/skills/`. No script in this repository writes either path. `~` here means the user home (`os.homedir()` or an explicit home override), not a path inside the repo. Project `.gemini/skills/` is a different tree: it is the Gemini CLI workspace mirror and stays that.
- Likely touch points for Planning: a small publisher next to `sync-harness-skills.mjs` (home trees must not be added to `REQUIRED_MIRROR_TREES`, which only lists committed project mirrors), plus a suite under `tests/skills/`. Bootstrap and `aai-sync` stay unchanged unless Planning finds they are the only place a downstream project obtains skills.

## Desired Behavior (To-Be)
- Workspace: after `node .aai/scripts/sync-harness-skills.mjs --write` (or an already-clean `--check`), every source skill exists at `.agents/skills/{skill_name}/SKILL.md`.
- Global: the publisher writes `{home}/.gemini/antigravity-cli/skills/{skill_name}/SKILL.md` for every universal skill.
- Shared: the same publisher writes `{home}/.gemini/skills/{skill_name}/SKILL.md` for every universal skill.
- Each copy keeps the source `name` and `description`. Body bytes match the source except for the existing `model:` carry/drop rule if Planning reuses that transform. Default assumption: home copies follow the `.agents/skills` rule (`carry`), because Antigravity is the consumer being added and that tree already carries `model:`.
- The publisher accepts an explicit home (fixture or real) and refuses to guess a second location. It does not read or write credentials.

## Acceptance Criteria
- AC-001: `node .aai/scripts/sync-harness-skills.mjs --check` exits 0, and the set of directory names under `.agents/skills/` equals the set under `.claude/skills/`.
- AC-002: Running the publisher with a fixture home creates `{home}/.gemini/antigravity-cli/skills/{skill_name}/SKILL.md` for every directory in `.claude/skills/` that contains `SKILL.md`, and creates no other skill directories.
- AC-003: The same run creates `{home}/.gemini/skills/{skill_name}/SKILL.md` for that same set, and creates no other skill directories.
- AC-004: A second run against the same fixture home exits 0 and leaves both trees byte-identical to the first run's result after the source is unchanged.
- AC-005: The publisher's tests set the home to a temporary directory. They do not create files under the real user home, and they do not follow `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, or `GEMINI_HOME` into a real corpus.
- AC-006: `.codex/skills` and the project `.gemini/skills` mirror still match `HARNESS_SKILLS.yaml` (`drop` plus README). `sync-harness-skills.mjs --check` is the witness.

## Constraints / Risks
- Official Antigravity CLI migration table (https://antigravity.google/docs/cli/gcli-migration/, read 2026-09-29) matches the three directories in this request: workspace `.agents/skills/`, Antigravity global `~/.gemini/antigravity-cli/skills/`, Gemini CLI shared `~/.gemini/skills/`. Plugin bundles use `skills/{skill-name}/SKILL.md` (https://antigravity.google/docs/plugins). This intake requires that directory-plus-`SKILL.md` shape, which is already what AAI ships.
- A third-party report claims current Antigravity global skills live in `~/.gemini/config/skills` instead of `~/.gemini/antigravity-cli/skills`. That claim disagrees with the official migration page and with this request. Planning verifies against the `agy` the operator runs. The targets above stand unless that check is recorded as a decision. Do not silently retarget.
- `REQUIRED_MIRROR_TREES` in `sync-harness-skills.mjs` is a closed list of committed project trees. Home directories are outside the repository and must not be appended there.
- `HARNESS_SKILLS.yaml` D2 still forbids a `.cursor/skills/` copy.
- No secret is referenced. Secrets preflight is skipped.
- Display number is not assigned in this intake. The durable id is `antigravity-cli-skill-paths`.

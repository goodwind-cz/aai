# Generate one more provider adapter surface from a single registry

## Summary

RFC-0017 phase 4 asks AAI to generate the per-provider surfaces from one
registry instead of maintaining them by hand. The skill trees already follow
that rule: `.agents/skills`, `.codex/skills` and `.gemini/skills` are generated
from `.claude/skills` by `.aai/scripts/sync-harness-skills.mjs` under
`.aai/system/HARNESS_SKILLS.yaml` (SPEC-0154). This change finds the
provider-adapter surface that is still hand-maintained with the largest measured
duplication or drift risk, and generates it from one declared source with a
`--check` drift gate.

## Motivation / Business Value

Each hand-maintained copy for a provider (Claude, Codex, Gemini, Cursor,
Copilot) can drift from the canon, and a drifted adapter silently tells one
harness something different from the others. The RFC evidence names four
discovery trees of 42 skills; those are done. What remains is smaller and
scattered, so the slice must be chosen by measurement, not by guess.

## Scope

In scope:

- Planning measures every remaining provider-adapter surface in this repo and in
  a scratch `aai-sync` target (this repo tracks `.aai/`; downstream ignores it),
  for example the instruction shims (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`,
  `.github/copilot-instructions.md`, `.cursor/rules/aai.mdc`) and the copies
  `aai-sync` installs, per-harness hook or settings files, per-harness
  capability or model tables, and skill catalogs or READMEs not yet generated.
- For each: bytes, number of copies, how much is shared text, whether a guard
  already compares it, and observed drift (git history).
- One bounded slice: the surface with the largest measured duplication or drift
  risk becomes generated from one registry, with a `--check` mode that fails on
  divergence and is wired into an existing suite or CI gate.
- Signing the owner-directed merge of #501 (merged 2026-10-25 with "Mergni #501
  (Recommended)"): the 6 unsigned contract amendments of
  `merge-cleanup-resolves-framework-friction` (SPEC-0218, SPEC-0221, SPEC-0223,
  SPEC-0252) are signed and their `fu-amend-*` trackers closed.

Out of scope:

- Anything already generated (the three skill mirror trees and their READMEs).
- Model routing tables beyond describing them; routing stays harness-universal.
- Process adapters (phase 5) and the platform adapters kept on purpose.
- A second slice: further surfaces are listed as follow-ups with their
  measurement.

## Affected Area

Provider-facing instruction and configuration files, the generator and its
registry under `.aai/scripts` and `.aai/system`, `aai-sync` if it installs the
chosen surface, the matching tests, and the product doc for the capability.

## Desired Behavior (To-Be)

One declared registry owns the chosen surface. Running the generator with
`--write` produces every copy; `--check` exits non-zero and names each copy
that differs. A hand edit to a generated copy is caught by the gate before
merge. Downstream installs receive the same generated bytes.

## Acceptance Criteria

- AC-001: A measurement note lists every remaining provider-adapter surface
  with bytes, copies, shared share, existing guard and drift history, measured
  in this repo and in a scratch aai-sync target, and names the chosen slice and
  why.
- AC-002: The chosen surface is produced by a generator from one declared
  registry; every copy in the repo equals the generator output.
- AC-003: `--check` exits non-zero on any divergence and prints one line per
  differing copy; it exits 0 when all copies match. The description states
  exactly what it compares.
- AC-004: The check runs in an existing suite or CI gate, so a hand edit to a
  generated copy fails before merge.
- AC-005: If `aai-sync` installs the surface, a scratch install receives the
  generated bytes and the check passes there.
- AC-006: The 6 contract amendments of merge-cleanup-resolves-framework-friction
  are signed by the owner's merge direction for #501 and their trackers are
  closed; `spec-amend list --strict` exits 0.
- AC-007: The product doc for the capability describes the registry, the
  generator and the gate; remaining surfaces are filed as follow-ups with their
  measurements.

## Verification

- The generator suite (new or extended) passes with `--check` red on a planted
  divergence and green on the generated tree.
- `spec-amend list --strict` exits 0 and the #501 trackers read `done`.
- Full sweep once before close.

## Constraints / Risks

- Node stdlib only (docs/TECHNOLOGY.md); no YAML dependency.
- A shim that differs per provider for a real reason must keep that difference
  declared in the registry, never flattened.
- Downstream ignores `.aai/`, so install effects are measured on a scratch
  target, not in this checkout.
- Secrets preflight: no secret referenced.

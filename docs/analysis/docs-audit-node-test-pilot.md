# Docs-audit body-lint Node test pilot

The five selected body-lint behavior groups now call the existing pure `lintBody` export through `node:test`. The Bash suite still owns CLI rendering, strict/report behavior, file predicates, hooks and real-corpus checks. The ordinary `aai-docs-audit` framework run invokes the Node file once after dependency checks and before fixture setup. The exact Node path is mapped under the always-on suite. Production audit logic, the test wrapper, scheduler, hooks and CI workflow did not change.

## Fixed measurement

The matched workload was fixed before samples: B sources the pinned original Bash suite in an independent disposable checkout, assigns an absolute `TEST_DIR`, and calls M1–M5 once in order using `baseline-five.sh`. It does not call unrelated `setup_fixture`. Each B invocation creates five Git fixture repositories and launches the audit CLI five times; those are counts from the fixed driver and legacy source, not process instrumentation. F invokes `bash .aai/scripts/aai-run-tests.sh node --test tests/skills/lib/docs-audit-body.test.mjs` in the disposable candidate. F runs ten named Node cases (five LF migrated families and five added CRLF variants), with eleven unique fixture strings per line ending, 24 `lintBody` calls because M1 checks its detail with a second call, and no test-case filesystem/Git/child-process work.

Both used the same local macOS arm64 host, Node v26.12.0, Bash 3.2.57, Git 2.54.0, wrapper, serial width and 120-second focused timeout. The baseline tree and full candidate file SHA-256 identities are in `identity.json`; production core has the same SHA-256 on both sides (`1a94f38da077a6c3eb1017b9950b2c4f3c69f7b4562bdf34f0a5110d87307190`). The candidate is an uncommitted overlay on the pinned baseline commit, so its file hashes, rather than its unchanged `HEAD`, identify it. All raw wall times below come from an external monotonic timer around the wrapped command; the post-step scoped reaper runs afterward and reported zero reaped trees each time. The paired runs alternated B/F order, following one declared untimed warm-up for each side. Every attempted matched run exited 0; there were no exclusions, timeouts or failed pairs. Two exploratory fixture-comparison helper attempts failed before the final byte comparison: first a JavaScript string escaping error in the checker, then an extractor that omitted the two `printf` fixtures. Those were inspection-tool defects, not B/F or integration runs; their original tool output was not archived. The corrected helper's 11/11 comparison is archived.

All five F samples were below the RFC's ten-second hypothesis. Both ran one suite, with one isolated, one fully seeded, and no skipped suite. The candidate run visibly executed ten named Node cases before fixture setup. These two individual observations do not establish an ordinary-suite median or speedup; the candidate's doc/ledger overlay also differs from the pinned baseline corpus. Both wrapper logs printed a `AAI-TRIPWIRE FAIL` diagnostic for a `docs/ai/tests/test-runs.jsonl` append while the framework attested the suite clean and the wrapper returned 0. That append is framework telemetry in the disposable checkouts, disclosed here rather than treated as a source edit. No broad 109-suite sweep was run by Implementation.

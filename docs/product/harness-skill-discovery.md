# Skill descriptions name the prompt that runs them

## What it does

Agent harnesses (Claude Code, Codex, Gemini and others) show only a skill's
one-line description until the skill is loaded. Every AAI skill wrapper now
ends that line with a pointer to what actually runs it, for example
`Run by reading .aai/SKILL_SHIP.prompt.md first.`. An agent that acts on the
listed summary alone still learns where the real instructions are. A check in
`sync-harness-skills.mjs --check` fails when a shipped wrapper loses its
pointer, points at a missing file, or grows past the length harnesses accept.
`/aai-ship` also no longer ends a turn silently: every turn ends with a pull
request, a decision block, a printed stop, the question for the need, or
while it waits for a dispatched role to return.

## How to use it

Nothing to do in a project: `/aai-update` (or `aai-sync`) installs the new
wrapper descriptions into every skill tree it manages. To check a tree by
hand:

```
node .aai/scripts/sync-harness-skills.mjs --check
```

A clean tree prints `OK: <n> wrapper description(s) name their canonical
source`. A broken wrapper prints `DIVERGE pointer <skill>: <reason>` and the
command exits 1. A project's own skills (names without the `aai-` prefix)
and wrappers generated by `/aai-bootstrap` are not checked.

## Data model

- `.aai/system/HARNESS_SKILLS.yaml` gains an optional `pointer:` section with
  one row, `<max characters>|<source of the limit>`. It ships as
  `1024|agentskills.io/specification: ...`. Without the section no pointer
  check runs.
- Each wrapper's frontmatter `description` is a YAML-safe one-line scalar
  that ends in the pointer sentence; four descriptions are now quoted.

## Interfaces and contracts

- `sync-harness-skills.mjs --check`: exit 0 clean, exit 1 with one
  `DIVERGE pointer` line per wrapper that fails (missing pointer, missing
  target, pointer not matching the wrapper body, body naming no source,
  over the limit, unsafe YAML), exit 2 for a malformed `pointer:` section
  (also in `--write`, before any write).
- Pointer shapes: `Run by reading .aai/SKILL_<NAME>.prompt.md first.` for
  prompt-driven skills, `Run via node .aai/scripts/<name>.mjs.` for the two
  generator skills (`aai-overview`, `aai-factory-report`).
- `/aai-ship`: the required or L3 worktree gate now parks the ride as
  `[HITL-7]` through `state.mjs set-human-input`, so `ride-status.mjs`
  reports the block instead of `blocker: none`.

## Limits and non-goals

- Nothing in a consumer project runs the check automatically after a sync
  yet; it runs in this repository's CI.
- A project skill named `aai-project-<topic>` is still checked and would be
  reported; tracked as a follow-up.
- A core-profile project may hold wrappers whose prompt is only in the
  extended profile; the check accepts those when `PROFILES.yaml` lists the
  file as extended.
- Whether a model obeys the end-of-turn rule cannot be tested; the test pins
  the rule text and proves the park command blocks the ride in STATE.

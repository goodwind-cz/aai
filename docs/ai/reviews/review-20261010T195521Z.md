## Findings

### B-1 (BLOCKING): TEST-1375 arm 1 in test-aai-spec-amend.sh is red

V3 signed the 13 "unprovable restamp" records. TEST-1375 pins those records on the live ledger as `contract/unsigned-tracked`.

The test's purpose is that they are back in the **contract** lane. Being owner-signed is consistent with that purpose. Its literal bucket check is not.

Remediation (needs a PFA):
- Widen arm 1 to require `amendment_class === "contract"` with bucket `unsigned-tracked`, or `signed` through a later overlay that cites an owner authority.
- Re-run V4 in full.

### B-2 (BLOCKING): TEST-029 in test-aai-follow-ups.sh is red

The spec's "Registry items closed by this scope" line contains `fu-amend-*`. verify-closures parses that as the id `fu-amend`, which does not exist, so it reports a MISS outside the allowlist.

Remediation: reword that line so that it carries no `fu-`-shaped token. For example, list the 34 ids, or say "the amendment trackers listed under Spec-AC-08".

### B-3 (BLOCKING): TEST-026 is a live-ledger pin on moving state, in the default suite

TEST-026 asserts:
- the two kept trackers are still `open`;
- every other record present at da1abba5 still has its bucket.

The very next `/aai-merge` of the routing-tables ride will:
1. sign that ride's 2 records;
2. close `fu-amend-update-installs-ref-guar-f8caa1`.

Both steps are done by this feature, and both turn main red. B-1 shows the same mechanism has already happened once, which is the LEARNED 2026-09-05 immutable-pin lesson.

Remediation: assert what V3 did instead of a frozen fold. The overlays citing the authority ts sign exactly the 202 keys and nothing else. The 34 closes carry actor merge-cleanup and are dated at V3. No overlay or close citing the authority ts touches any other record or tracker. Alternatively, move TEST-026 out of the default run order.

### NB-1 (NON-BLOCKING, P2): the backlog authority is not scoped to signing

`sign-merged` accepts any single by=human `hitl_decision` or `directed_merge` that has a non-empty answer. Two consequences:
- A `directed_merge` (words that authorize one PR) can authorize signing the whole backlog.
- An unrelated hitl_decision can do the same.

Recommended disposition: promote to a follow-up (`fu-sign-merged-authority-unscoped`). Restrict the authority to `hitl_decision`, or require the decision's ref_id/question to concern signing. Recorded as residual R1 territory.

### NB-2 (NON-BLOCKING, P3): sign-merged's origin default is undocumented

HELP lacks `sign-merged`. The default `--origin` is the main checkout, which is correct for apply but surprising for a backlog run whose overlays must ship in a PR. Neither HELP nor the product doc says this, and the `no_owner_decision` refusal does not name the ledger it read.

Recommended disposition: remediate in tree. Add a HELP line and one product-doc sentence, and include the ledger path in the refusal detail.

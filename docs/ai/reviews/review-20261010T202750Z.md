## Findings

### NB-1 (NON-BLOCKING, P3): sign-merged would sign `unclassified` contract records

`runSignMerged` selects `mine.filter((i) => i.bucket !== 'signed')`. Apply's `signable()` additionally drops `bucket === 'unclassified'`, which is assumption A4: "`unclassified` records are not signed by either writer".

How it bites: an `owner_signoff`-less contract record, whose tracked_by is back-filled by an overlay to an open fu-amend tracker of a merged ride, would get an owner signature. That converts a `list --strict` violation into `signed` instead of surfacing it.

There is no live bite: strict is at 0, so no unclassified records exist today. It would still leave a false record if it fired, so disposition (d) does not apply.

Recommended disposition: **remediate in tree**. Reuse `signable()`'s first two filters in the sign-merged record loop, or add `.filter((i) => i.bucket !== 'unclassified')`, plus one fixture arm in TEST-025. Alternatively, promote it to a follow-up: `fu-sign-merged-signs-unclassified`, P3.

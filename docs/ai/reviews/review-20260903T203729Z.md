## Judgements the dispatch asked for

**1. Is `classify --signoff none` co-creating the right design?** Yes. The
alternative — a `classify` that only writes the overlay — is precisely the F1
defect: a refusal naming a remedy that leaves the refusal standing. Filing
against the EFFECTIVE tracked id read back off disk (line 788-803) is the
correct ordering, because the fold lets a record's own `tracked_by` outrank
any overlay's, so filing before the re-read could manufacture an orphan.

Half-state analysis (traced, not assumed): a crash between the overlay append
and the item append leaves the record `unsigned-untracked`, so `--strict`
still refuses and a re-run repairs it — on the second run `target.tracked_by`
is already the first overlay's id, so the same id is filed and no orphan or
duplicate results. A crash after the item append leaves a correct state; a
re-run appends a redundant same-valued overlay (latest-wins, harmless) and
files no second item. An item that already exists and is open is reused; one
that is closed reopens under a stamped id, and a same-minute second reopen
gets the `-2` suffix. I exercised all three branches on fixtures.

The one place the co-creation is *under*-guarded is NB-B above: the
`--tracked-by` escape hatch skips `pickAmendItemId` entirely, so the
closed-item invariant that function documents does not hold on that path.

**2. `add` left fail-OPEN.** The prose fix is sufficient *for the gate*: `add`
is named as a NOT-remedy in five places (the stderr refusal, `USAGE`,
AUTONOMOUS_LOOP §6a, ROLE_COMMON, SKILL_PR), and TEST-013 arm 4 pins both that
`add` still never refuses and that it does NOT clear a pre-existing untracked
record. Crucially the gate is fail-CLOSED, so an operator who runs `add` by
mistake gets refused again with the correct line — the loop terminates
correctly. The residue is one spurious amendment record on an append-only
ledger, which is a cost, not a stuck state. The measured argument for not
making `add` refuse (no target; "already exists" needs a fuzzy `(spec, ref)`
match; 3 of 6 live rides amended one spec more than once) holds. Accepted.

294 and 297 keep exact `rec.type` for `follow_up` and `follow_up_status`. The
asymmetry is the correct direction — widening what the gate CATCHES can only
turn green red; widening what EXCUSES an amendment would launder one. TEST-014

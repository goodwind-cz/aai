## Findings

### NB-1 (NON-BLOCKING), orchestration-dispatch.mjs:1919: the unpriced NOTE fires after the backstop swapped the override away

Post as PR thread: The unpriced NOTE is decided from `applied` (the consumer's override id) before `suggestModel` runs. On a Validation dispatch, the validator-independence backstop can replace that id with a shipped one. Then `suggested_model` is a priced id, but stderr still says `claude/Validation -> acme-model-1 is unpriced: metrics cannot cost the run`. Repro `docs/ai/reports/consumer-config-routing-override/repro-fallback-unpriced-note-after-backstop-swap.sh` (exit 0, REPRODUCED): a consumer pins Validation (and its implementer) to `acme-model-1`, the dispatch suggests `claude-sonnet-5-5`, and the NOTE still claims the run cannot be costed. The spec counts a swapped override as "applied" (R6), so the line is spec-conformant. Its wording is still false in that case. Suggested fix: compute the NOTE after `suggestModel` and either skip it when `out.suggested_model !== applied`, or append "(replaced by <id> for validator independence)". Recommended disposition: promote to a P3 follow-up (advisory stderr only, no wrong dispatch).

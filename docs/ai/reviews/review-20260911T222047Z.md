## The two BLOCKING findings, in plain terms

**BLOCKING-1 — the gate half-closes the pair and then certifies itself clean.**
`spec-freeze.mjs:80` is the only writer of `status: implementing`, and it writes
it to SPEC docs. Intake docs go `draft -> done` (`close-work-item.mjs:212`
FLIP_ELIGIBLE accepts `draft`). Census: `docs/issues` has 45 `draft`, 223 `done`,
**0 `implementing`**; `docs/specs` has exactly one `implementing` — this scope's
own spec. So the surviving arm can, in this repository's conventions, only ever
fire on a spec. `pairItems` (:250-265) resolves a spec only *from* a primary
item, and the primary is never an item, so `--spec` is dead in production and
`--apply` runs `close-work-item.mjs --ref <spec-slug>` alone. The intake doc —
the artifact issue #352 is entirely about — stays `draft` with `links.pr: []`,
and the follow-up `--check` prints CLEAN. The scope's headline AC (Spec-AC-08,
"SHALL end with its intake doc at `status: done`") is proven only on a fixture
shape the corpus never produces. Note the remediation's fixture flip moved
TEST-003/004/006/009/010/011 *off* the production-realistic shape (intake
`draft` + incidental non-doc path) and onto the only shape the surviving arm
catches; the assertions still bind, but they bind to an unreal fixture.

Amendment item 2 half-sees this ("PRD-0001 itself no longer surfaces as its own
named item") but frames it as a detection/recall question and concludes the push
still reddens. The `--apply` completeness consequence, and the false CLEAN that
follows it, are not disclosed anywhere in the spec, and D3 states the pair case
as if it were always handled ("one `close-work-item.mjs` invocation with
`--spec`, never two").

**BLOCKING-2 — `umbrella: true` is not exempt, and there is no dial.**
`close-reconcile.mjs` contains zero occurrences of `umbrella`.
`docs-audit-core.mjs:1228-1242` suppresses the false-open verdict for a
deliberately-open multi-phase parent, a suppression shipped *as* PR #207 because
this exact class kept re-tripping. `docs/rfc/RFC-0012` is `status: implementing`
+ `umbrella: true` today, and commits `4b74cedc` (#202) and `a82d916b` (#207)
both touched it in that state. Under the shipped gate each of those pushes
reddens `main` and prints a remediation that closes a live umbrella parent. D5
removed every dial on the grounds that the job blocks nobody — true for a
correct signal, but a false positive here has no legitimate clearing action, so
`main` stays red until someone edits the doc or the workflow. R5 accepts noise
from *true* positives only; D2 names avoidable false positives as the class that
"would make the gate unusable downstream" and claims they are designed out. The
cheapest fix mirrors the existing library: skip an item whose frontmatter
`umbrella` is `true`, and cover it with a fixture.

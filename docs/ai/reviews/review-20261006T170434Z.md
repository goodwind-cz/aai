## Findings

### B1 — BLOCKING: exclude nested Git metadata from the installed snapshot

At `.aai/scripts/worktree-seed.mjs:39`, recursion excludes only the top-level AAI cache and directories named `skills.local`. It accepts `.git` at any depth as ordinary installed content. This contradicts D2's explicit `.git` exclusion and Spec-AC-05's zero-excluded-runtime-files promise.

Reproduced in `/tmp/aai-review-worktree-seed.RcQ2pE` using fixture-local repositories and the shipping helper without modifying it:

1. Initialize a custom skill repository in `source/.claude/skills/custom` and seed a registered project target. The helper exits 0 (`SEEDED: 19 copied`) and `target/.claude/skills/custom/.git/config` exists.
2. Commit that skill's SKILL.md, create a linked skill worktree at `source/.codex/skills/custom-linked`, and seed a fresh registered project target. The helper exits 0 (`SEEDED: 44 copied`). The copied skill's `.git` file contains:

   `gitdir: /private/tmp/aai-review-worktree-seed.RcQ2pE/source/.claude/skills/custom/.git/worktrees/custom-linked`

3. `git rev-parse --absolute-git-dir` in both the source and copied skill returns that same absolute directory. Git operations in the target skill therefore use source-owned repository state. No mutating Git operation in the copied skill was needed to prove the coupling.

This is a concrete isolation failure, not solely an unwanted extra file. Exclude `.git` entries whether directories or regular gitfiles before traversal, and add behavioral regressions for both forms. Keep the skill's ordinary files in the copied inventory. Re-run the existing snapshot and refusal tests. This finding blocks PR/merge readiness and fails both verdicts.

### NB1 — NON-BLOCKING, P2: unrelated unavailable worktree breaks valid setup

At `.aai/scripts/worktree-seed.mjs:65`, `worktree list --porcelain` is mapped through `realpathSync` for every registered checkout. A valid source/target pair does not require every other worktree to be mounted or present. Git deliberately retains registrations for temporarily unavailable worktrees.

The scratch probe first seeds a valid target successfully. It then creates a separate sibling worktree, temporarily renames that sibling directory, and seeds the unchanged target again. The second seed exits 1 with:

`WORKTREE-SEED-REFUSED ENOENT: no such file or directory, lstat '/private/tmp/aai-review-worktree-seed.RcQ2pE/temporarily-unavailable'`

The sibling is restored afterward. Validate membership of the intended target without requiring unrelated paths to resolve; tolerate missing unrelated registrations without pruning them. A regression should keep a registered unavailable sibling while proving that the valid target still seeds.

Recommended disposition: **remediate-in-tree** alongside B1. This was observed and is P2, so it is not eligible for accepted-residual disposition. If deferred, the orchestrator must file a typed follow-up or tracked ref and record that artifact in review notes before closeout. No follow-up was filed by this read-only reviewer.

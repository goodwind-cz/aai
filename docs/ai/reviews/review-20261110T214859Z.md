## BLOCKING

**B1, tests/skills/install-parity.Tests.ps1:72.** `$want = @($l.Out | ConvertFrom-Json)`. In Windows PowerShell 5.1, ConvertFrom-Json sends a top-level JSON array down the pipeline as ONE object, and `@()` then wraps it a second time. The repo already documents this quirk at tests/skills/aai-win-dispatch.Tests.ps1:1148-1152. Under 5.1, `$want.Count` is 1, so the `-BeGreaterThan 0` check still passes, but `$want -join ','` gives `System.Object[]` and the next `Should -Be` fails. Both 5.1 legs (windows-5_1 and windows-wsl1) go red. The validation pass ran Pester only under pwsh 7, so it could not see this.
Repro (pwsh 7, using -NoEnumerate to reproduce 5.1 behaviour): `@('["SY-01","UP-01"]' | ConvertFrom-Json -NoEnumerate) -join ','` prints `System.Object[]`.
Fix: `$want = @(($l.Out | ConvertFrom-Json) | ForEach-Object { $_ })`. Alternatively, call `list --matrix smoke` without `--json` and split the output on newlines.

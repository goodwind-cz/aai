## Decision 1 — is BLOCKING-1 closed?

Yes. The executor contract is `test-framework.sh:948-953`: `--skill` resolves only `$SCRIPT_DIR/test-<name>.sh`. `--check` now requires, for every planned name, a top-level `$skills_dir/test-$name.sh` (`shard-plan-check.sh:108`), on top of planned set = recursive find set and no duplicates. Every on-disk basename is therefore planned, and each planned name is runnable by its leg. The original shape (a weighted suite moved into a subdirectory) fails `select` and every leg loudly, and TEST-1440 pins it with a positive and negative control.

Silent-loss search after the fix:
- Nested-only suite: loud (TEST-1440, validator probe A).
- Twin (top-level + nested, same basename): the selector never dedupes (`discoverSuiteNames` pushes every file), so the plan names it twice and the dup arm fails loudly. The silent variant needs a plan listing it once. The only producer is the selector. The moved-merge-ref leg case needs the twin to exist on the base, and the twin can't get there green: the PR that adds it fails `select` (the shard step has no `if:`), and so does every later run on a base holding it. **NB-A rated NON-BLOCKING (P3, defence in depth).**
- Unsafe names: whitespace breaks `awk $3` and fails the set check loudly. Glob characters are blocked by the regex arm. Even without the arm, the leg keeps the literal unless a matching file exists in the repo root. Symlinks are excluded by both enumerations and by the pre-change bare sweep alike, so nothing regresses there.
- Remaining framework defect (`exit 2` swallowed through process substitution) is pre-existing and tracked as `fu-framework-discover-exit-swallowed` (filed, P2, per validation report). The plan check now keeps sharded mode from ever reaching it.

**NB-B rated NON-BLOCKING (P3).** The clause is implemented and works (P3), but no test pins it. Removing it has no silent-coverage path I could construct.

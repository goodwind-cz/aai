### NB-1 — source entry types are not validated consistently

At `.aai/scripts/sync-harness-skills.mjs:170-180`, `listSourceSkills()` checks
only real directories and uses `existsSync()` for their `SKILL.md`. Two scratch
fixtures demonstrate the incomplete boundary:

1. A `.claude/skills/evil` symlink to an external directory containing a valid
   `SKILL.md` is ignored. `--write` does not project it, and a following
   `--check` exits 0 while all mirrors lack `evil`.
2. A real `.claude/skills/a` directory whose `SKILL.md` is a directory passes
   the existence check and reaches `readFileSync()` at line 363. The command
   exits 2 with a generic `EISDIR` stack trace that does not name skill `a` or
   its path.

This is non-blocking because the shipped source contains only regular authored
directories/files, the broad bash parity arm independently notices a symlinked
source skill, and both cases fail or are caught before mirror mutation in the
supported suite path. It still weakens the generator's standalone structural
contract and operator diagnostics.

Recommended disposition: **remediate-in-tree**. Refuse symbolic-link entries in
the authored source tree and require `lstat(SKILL.md).isFile()` before adding a
source skill. Both refusals should exit 2 and name the offending repo-relative
path; add regressions for a source-directory symlink and a directory at
`SKILL.md`.

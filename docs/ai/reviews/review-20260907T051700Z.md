## What was judged, and what was found true

The dispatch asked five specific questions. Answers, with evidence.

**1. Does the fixture reproduce the production shape it claims?** Yes,
faithfully, on every axis the code reads. Production carries
`docs/product/simple-and-friendly-to-use.md` (`id: simple-and-friendly-to-use`,
`type: product`, `status: current`) and
`docs/requirements/PRD-0001-simple-and-friendly-to-use.md` (same `id`,
`status: draft`). The fixture mirrors both families, both statuses, the shared
id and the slug-named brief. The two docs enter the scan by the two DIFFERENT
admission branches production uses — `slugFamilyForPath` for the product-family
file, `DRAFT_FILE_RE` for the `PRD-DRAFT-` basename — which is confirmed
empirically, not read off the source: the unguarded run reports
`shadowed-slug.md (terminal (current))`, and only an admitted
`docs/product/shadowed-slug.md` can produce that string. The one deviation is
`type: change` on both fixture docs (see cannot_verify).

**2. Is TEST-004c independent of the other arms?** Yes as an assertion. It
checks its own brief, produced by its own doc pair, after the real sweep; it
shares no state with TEST-003/004b and reads none of TEST-005's counts. Proven
by neutralizing TEST-005's two count needles and running the mutated script:
TEST-004c reddens on its own. It IS masked in a whole-suite run — TEST-005's
`would prune 3` fails first and `log_fail` exits — but that is fail-fast
reporting order, not a dependency.

**3. Was TEST-005's needle 2 -> 3 the right call?** Yes, and it is a
strengthening, not an accommodation. The new fixture adds exactly one KEPT brief
and zero prunable ones, so `kept_open: 3` is arithmetically forced while the
sibling `would prune 3` needle is UNCHANGED. Under the reverted guard the
unchanged needle is the one that fires first (`would prune 4 ... kept 2`), so the
old assertion still bites at exactly its old strength and now additionally pins
the shadow-keep. Nothing was relaxed to make a new fixture fit.

**4. Behaviour or current output?** Behaviour. TEST-004c asserts that a file
survives a real sweep — the outcome the rule is about — not a formatted string.
Its failure message states the rule ("a non-terminal status beats a terminal one
for the same id") in general terms. R1 is precisely that the general claim is
verified along one scan order out of two, with the other silently vacuous.

**5. Linux/CI differences.** One, and it is R1. Everything else is clean: no
PowerShell mirror exists for this suite (`tests/skills/*.ps1` is release,
update, win-dispatch only), so no Windows leg went stale; `mkdir -p`, `printf`
and the heredoc are portable; `mktemp -d "${TMPDIR:-/tmp}/..."` is unchanged;
no `sed -i` or `date` portability traps were introduced; the suite stays
bash 3.2 compatible.

## Verdict 2: code quality (fail)

### BLOCKING-1: plan proven recursively, executed top-level only; suites silently dropped
- Files and lines: `tests/skills/lib/shard-plan-check.sh:72` (the recursive find is the only membership proof), `.github/workflows/skill-suite.yml:227-232` (the leg passes names to `--skill`), `.aai/scripts/select-suites.mjs` `discoverSuiteNames` (recursive walk). The pre-existing executor is `tests/skills/test-framework.sh:949-954` (`--skill` resolves `$SCRIPT_DIR/test-<name>.sh` only) and `:2069-2072` (`done < <(discover_tests)` discards the subshell's `exit 2`).
- Reproduction (scratch clone, scratchpad `review-ci-shard/`):
  1. Real framework with `--skill aai-zz-a --skill aai-zz-b --skill aai-zz-c`, where zz-b is nested and exits 1 and zz-c exits 1. Output: "Test file not found … test-aai-zz-b.sh", "Found 1 test(s)", **rc=0**.
  2. Same tree with weight rows for the stubs: selector plus `--check` print `shard_ids=[1,2,3,4]`, rc 0. `aai-zz-b` is position 7 of 26 in shard 3, so 19 suites after it would be skipped and the leg would stay green.
- Trigger: moving an existing suite into a subdirectory. Its weight row and suite-map row stay, and hygiene test_090/the row-count pin only glob the top level. A brand-new nested suite without a weight is scheduled first in its shard, so that case fails loudly. That is why validator NB6 ("fails loudly") holds only for the unweighted case.
- Why blocking: this change exists so that coverage never shrinks silently. Before it, the bare sweep ran nested suites. After it, they and the rest of their shard can vanish while the gate is green.
- Fix (in scope, small): in `--check`, after the set equality, require that every planned name matches `^[A-Za-z0-9_-]+$` and that `[[ -f "$skills_dir/test-$name.sh" ]]`, and fail naming the offender. Add a fixture test with a nested suite. Optionally, make the selector refuse the same way. Separately, as a suggested follow-up for a pre-existing defect that also affects selected mode, `fu-framework-discover-exit-swallowed`: `discover_tests`' `exit 2` is lost through process substitution.

### NB-1 (P2): TEST-1423 bound goes red on any unweighted new suite
- File and line: `tests/skills/test-aai-suite-select.sh:203-214`.
- Reproduced: adding `tests/skills/test-aai-newsuite.sh` with no weight row gives "FAIL: TEST-1423: largest shard weight-sum 1113 exceeds bound 1056".
- Fix: compute `total` and `max_w` from the plan's emitted `weight=` values, not from the file. The bound then follows the plan actually scheduled.
- Recommended disposition: (a) remediate in tree.

### NB-2 (P3, validator NB2): `uniq -d | head -n1` at `shard-plan-check.sh:78`
- It runs only on the failure path, and the exit stays non-zero, so it can never produce a false pass. The risk is losing the offender diagnostic.
- It contradicts the file's own header claim (lines 24-28).
- Fix: `awk 'NR==1'` instead of `head -n1`, or write `uniq -d` to the temp file and read its first line.
- Recommended disposition: (a) remediate in tree. It is a one-line change and is being touched for BLOCKING-1 anyway.

### NB-3 (P3, validator NB1): `out="$(...)"; rc=$?` at `test-aai-suite-select.sh:507,509`
- Under `set -e` the `rc` check is dead code. Failure is red without a message. It is never green.
- Fix: `rc=0; out="$(...)" || rc=$?`, the shape `run_shard` already uses.
- Recommended disposition: (a) remediate in tree alongside the above. (d) is acceptable instead: "accepted residual: dead diagnostic, failure still red".

### NB-4 (P3, includes validator NB3): workflow pins weaker than AC-05's wording
- `test-aai-suite-select.sh:439-461`: no "shard step has no `if:`" pin, and the fetch-depth check is a file-wide count.
- Both mutations fail loudly or narrowly in CI rather than silently dropping coverage.
- Disposition (remediation, 2026-10-03): (d) accepted residual — assurance-strength finding only (both mutations fail loudly or narrowly in CI, never silently), no observed bite, no false record left anywhere. Not remediated in this pass; out of scope for BLOCKING-1.

### INFO (non-gating)
- Validator NB5: `--check` does not validate the shape of shard ids. Every malformed shape ends in invalid JSON, which is a loud matrix error, or in awk numeric equality that still extracts the suites. No silent path was found.
- The shard step now runs before the mode decision. A selector or plan defect therefore fails `select` for selected-mode PRs too. This is fail-closed and intended by D5.
- `--weights` resolves against `--repo-root`, not the cwd. This is consistent with `--map`.
- Checked and found sound:
  - A crashed selector (`FULL_RUN internal-error`) or empty selector output makes the set mismatch, so `select` fails and `gate` fails.
  - An orphan weight row is ignored.
  - A malformed weights file still yields a complete plan.
  - Duplicate basenames are caught by the dup check.
  - Symlinks are excluded consistently by both enumerations.
  - A moved merge ref is caught by the leg re-check.
  - A skipped or failed `select` fails `gate`.
  - An empty or unparseable `shard_ids` errors the matrix, so `skills-full` is not `success`.

## Decisions (each one the orchestrator asked for, stated explicitly)

### D1 — What triggers the close gate downstream in a repo with no CI at all
A vendored `pre-push` hook, written by `install-pre-commit-hook.(sh|ps1)` as a THIRD hook (selection token `close-gate`, marker `# AAI:CLOSE-GATE`), runs `node .aai/scripts/close-reconcile.mjs --check --range <A>..<B>` once per pushed ref. Git feeds the hook `<local ref> <local sha> <remote ref> <remote sha>` on stdin and the remote name as `$1`. Per line:
- local sha all-zero (a deletion) → skipped; nothing to check.
- remote ref is `refs/heads/<default>` (the default branch per R1) → range `<remote sha>..<local sha>`; an all-zero remote sha (first push of the branch) falls back to `<local sha>^..<local sha>`, byte-for-byte the rule `.github/workflows/close-gate.yml:46-50` already applies.
- any other remote ref (a feature branch) → range `<merge-base of refs/remotes/<remote>/<default> and local sha>..<local sha>`, i.e. the branch's own delta. When `refs/remotes/<remote>/<default>` cannot be resolved (never fetched), the hook prints `AAI:CLOSE-GATE NOTE: <ref> skipped — refs/remotes/<remote>/<default> unresolvable` and moves on.
- Why the feature-branch push is checked at all: `.aai/SKILL_PR.prompt.md` step 4c ("CLOSE BEFORE PUSH", line 181) already moves the close ceremony to BEFORE any push exists, so at push time a branch that delivers frozen work should carry terminal docs. The push is the last point a hook can see on the developer's machine; a server-side PR merge (GitHub, Azure) never runs a local hook and is observed only by CI (D5). This spec says so plainly rather than implying the hook sees merges.
- Verdict: the `close_gate` dial (D8), read from the PUSHED commit's config (`git show <local sha>:docs/ai/docs-audit.yaml`, the same "gate what is being shipped, never the worktree copy" discipline the pre-commit body applies at install-pre-commit-hook.sh:636-641), decides. `report-only` (the shipped default, and an absent file or key): print every close-reconcile line, exit 0. `enforce`: refuse (exit 1, push aborted) ONLY for a ref that targets the default branch; a non-default ref is ALWAYS report-only, because intermediate pushes (CI, draft PRs, review) legitimately precede the ceremony that step 4c performs at the end of a ride, and a hard block there would turn every WIP push into a refusal with no operator to override it — the exact hazard the intake's Constraints name.
- Degrade-with-NOTE: `node` absent → `AAI:CLOSE-GATE NOTE: node not found; close gate skipped`, exit 0. `close-reconcile.mjs` absent → NOTE naming the path, exit 0. close-reconcile exit 2 (unresolvable range) → NOTE with the range; under `enforce` for a default-branch ref that is a refusal ("the gate could not run" is treated as "the gate said no", the rule `check-vendored-script-deps.mjs` already states), under `report-only` it is a NOTE.

### D2 — Report-only versus enforce, and the shipped default
The shipped default does NOT change: `.aai/templates/docs-audit.template.yaml:45` stays `doc_number_guard: report-only`. Ground: M3 measured a legitimate false positive at commit time. What DOES change, and is called out as a BEHAVIOUR CHANGE for every downstream project on its next `/aai-update` (the installer runs on every successful sync, SKILL_UPDATE step 4), not as a fix:
1. The pre-commit hook now reaches `pre-commit-checks.sh`. Its CHECK 2 secrets detection exits 1 on a hit — commits carrying a detected secret are REFUSED where before they went through. CHECK 8 output appears on every commit that carries an unnumbered draft.
2. Roughly four seconds are added per commit (M4).
3. CHECK 8's `enforce` arm becomes merge-point-aware (this is the L3 edit): with `doc_number_guard: enforce`, a commit on the DEFAULT branch (R1) that fails the guard is blocked as today; a commit on any other branch prints the guard's findings plus ONE line `Doc-numbering guard: enforce applies on <default> only; on <branch> this is report-only`, and exits as report-only. Without this, wiring the hook would refuse this repository's own intake commits (M3) and every downstream project that had flipped the dial. The `.ps1` twin (pre-commit-checks.ps1:177-203) mirrors it.
The CHANGELOG `## [unreleased] — <title>` entry and the USER_GUIDE section (Spec-AC-11) state all three.

### D4 — `aai-doctor` reports an uninvoked guard, and how it knows
New category `CAT-18 Guard Wiring`. It owns a CLOSED table of guard → caller pairs: (`.aai/scripts/pre-commit-checks.sh`, hook `pre-commit`, marker `AAI:GUARD-CHECKS`) and (`.aai/scripts/close-reconcile.mjs`, hook `pre-push`, marker `AAI:CLOSE-GATE`). For each pair whose guard file EXISTS in the tree (a vendored layer without the script has nothing uninvoked, so no false positive), it resolves the effective hook path the way CAT-17 does (`git rev-parse --git-path hooks/<name>`, honouring `core.hooksPath` and linked worktrees — NOT CAT-12's `--git-common-dir` shortcut), and reports PASS when the file exists, carries the marker and is executable; otherwise WARN with a reason that names the guard, the hook, the missing marker (or the missing executable bit) and the installer command. One category, one line, both pairs summarised; `--json` carries `id: CAT-18`. It knows by the same evidence the installer attests (`attest_effective`, install-pre-commit-hook.sh:274-296): marker at the effective path plus the executable bit. It does not probe behaviour (a pre-push hook cannot be fed a synthetic push safely); Residual risk R4.

### D6 — Hook-file safety: the #414 class, designed around
The pre-commit hook this installer writes becomes: line 1 shebang; a marker-delimited block `# AAI:GUARD-CHECKS BEGIN` … `# AAI:GUARD-CHECKS END` whose interior is declared engine-owned in its own first comment line ("managed by install-pre-commit-hook; edit outside these markers"); then the existing `AAI:INDEX-AUTOGEN` body byte-for-byte as today. The block runs `bash .aai/scripts/pre-commit-checks.sh` from the repo root, prints `AAI:GUARD-CHECKS: pre-commit-checks.sh blocked this commit (rc=<n>)` and exits with that code when it is non-zero, prints `AAI:GUARD-CHECKS NOTE: .aai/scripts/pre-commit-checks.sh absent; guard checks skipped` and continues when the script is missing, and never touches the index. It must run BEFORE the index body's early `exit 0` at install-pre-commit-hook.sh:596, which is why it sits at the top.
Rules for an EXISTING file in the pre-commit slot, applying the SPEC-0199 lesson (rewrite only what the engine can prove it owns; otherwise add, never destroy, and name it):
- Ownership, for all three markers (`# AAI:INDEX-AUTOGEN`, `# AAI:REF-GUARD`, `# AAI:CLOSE-GATE`), is the marker OPENING a line: column 0, followed by a space, end of line, or a CR (a CRLF hook the `.ps1` twin wrote on Windows) — the shape every shipped body carries (`# AAI:INDEX-AUTOGEN — auto-regenerate …`). A marker merely mentioned inside a foreign hook's comment, or quoted inside a string, is NOT ownership: such a file is refused as foreign and is never deleted by `--uninstall` (validation round 1 NB3). Both twins test this on bytes (`has_marker_line` / `Find-MarkerLines`), never on decoded text, so a UTF-16 file — which decodes into the marker but carries no marker byte sequence on disk — is foreign. Exact whole-line matching, which the two GUARD-CHECKS markers use, is not available for these three: the shipped bodies themselves carry commentary after the marker on that line and their bytes are pinned (`PRECOMMIT_SHA256_BASELINE`).
- owned by `# AAI:INDEX-AUTOGEN` and NO guard block (every hook installed before this ride) → the block is INSERTED after the shebang line (or at line 1 when there is no shebang); every other byte of the file is unchanged, whether the file was engine output or a hand-merged foreign hook that adopted the marker via `--print`. Output names it: `Upgraded AAI pre-commit hook at <path>: added the AAI:GUARD-CHECKS block (pre-commit-checks.sh now runs on every commit; secrets detection blocks)`. An `# AAI:GUARD-CHECKS END` line with no BEGIN is refused by name rather than inserted above.
- carries exactly one BEGIN and one END line, BEGIN above END → the interior between the markers is compared with the shipped interior and replaced only when it differs; a second run leaves the file byte-identical, and `grep -c '# AAI:GUARD-CHECKS BEGIN'` is 1. The refresh copies every byte outside the interior as-is in BOTH twins — a raw non-UTF-8 byte in a user line and a missing final newline included (the `.sh` splices by line number with `head`/`tail`; the `.ps1` splices the byte array, never a `UTF8.GetString`/`GetBytes` round-trip, which re-encoded such bytes as U+FFFD in validation round 1 B2) — so `Refreshed the AAI:GUARD-CHECKS block … every other byte unchanged` is true on every path that prints it.
- END line ABOVE the BEGIN line (inverted markers) → refused BEFORE any write, exit 1, file byte-identical; the refusal names both line numbers (`'# AAI:GUARD-CHECKS END' (line N) BEFORE '# AAI:GUARD-CHECKS BEGIN' (line M)`) and `--force`. With inverted markers no interior can be located and a marker-scoped refresh would drop every line after the BEGIN (validation round 1 B1: 150 user lines lost with a success message). More than one BEGIN or END line → refused the same way (which block is the engine's cannot be proven).
- starts with a UTF-8 byte-order mark (`EF BB BF`) → refused by name, byte-identical: `sh` cannot start a hook whose first bytes are not `#!`, and inserting above the BOM would only bury the shebang on line 20 (validation round 1 NB1).
- carries neither marker (foreign) → refused, exit 1, file byte-identical, unless `--force`; the refusal names `--print guard-checks` (the new `--print` argument) beside the existing `--print`.
- `--force` keeps its contract: the whole slot is rewritten with the fresh body.
A selected slot that exists and is NOT a regular file (a directory, a pipe, a socket) is refused before the temp file is composed: `mv -f` into a directory moves the temp INSIDE it and exits 0, so the writer used to announce an install that never happened and leave a stray executable in the user's directory (validation round 2 B1; the temp-sibling write shape this ride introduced is what opened it, since `cat > "$HOOK_PATH"` had failed outright). Symlinks are not handled there — the dedicated lstat refusal owns them. Every success and refusal message the installer prints describes exactly the bytes its path leaves on disk (a refusal is printed only when nothing was written; `every other byte unchanged` only by a path that changed no other byte).
The pre-push slot follows the reference-transaction slot's contract (SPEC-0184 Spec-AC-02): a foreign file there refuses the WHOLE selected run before any slot is written, the refusal names `--print pre-push`, `--uninstall` removes only an AAI-marked file, and attestation covers exactly the selected set. Nothing outside a marker is ever deleted or rewritten by a plain run.

### R1 — Default-branch resolution (one rule, used by D1 and D2)
`git symbolic-ref -q --short refs/remotes/origin/HEAD` with the `origin/` prefix stripped; when that fails, `main`, and the caller prints ONE line `NOTE: default branch assumed main (refs/remotes/origin/HEAD unset)`. Used by the pre-push body (which remote to compare against, which pushes may be refused) and by CHECK 8 (which branch the enforce arm applies on). Each caller prints the resolved name in its own output so a test can observe both agree on a fixture whose origin/HEAD is `trunk`.

- `.aai/scripts/install-pre-commit-hook.ps1` — the same, mirrored: `-Hooks close-gate`, `$prePushBody`, guard block inside `$hookBody`, insertion and refresh of an existing marked file on BYTES on every path (`ReadAllBytes`, `Find-MarkerLines` over the byte array for the marker scan and the order check, a byte splice for the insertion and for the interior refresh, `WriteAllBytes` via a temp sibling) — never a Get-Content/Set-Content or `UTF8.GetString` round-trip (fu-ps1-setcontent-rewrites-seed-eol; validation round 1 B2): the file's encoding and line endings outside the touched range are preserved as-is. `Test-MarkerOwned` is the one byte-level ownership predicate every foreign check, "already installed" check, `-Uninstall` and attestation consult.
- `.aai/scripts/pre-commit-checks.sh` and `.ps1` — CHECK 8 only: resolve R1, compare with `git symbolic-ref -q --short HEAD`, downgrade `enforce` to report-only off the default branch with the one NOTE line. No other check is touched (fu-pre-commit-checks-pipe-grep-q stays open).
- `.aai/scripts/close-reconcile.mjs` — grammar table, `--platform` flag, `import { classify, extractHost } from './pr-platform.mjs'`, platform probe over `git remote get-url origin` in `--root` (a failing probe is `none`), `parsePrNumber(commits, grammars)`, refusal text (D3). `close-work-item.mjs` is NOT touched (hash-pinned by four suites).

Data flows:
- commit → `.git/hooks/pre-commit` (effective path) → guard block → `bash .aai/scripts/pre-commit-checks.sh` → rc → block exits with rc or falls through to the INDEX-AUTOGEN body.
- push → `pre-push` → per stdin line: R1 default, range per D1 → `node .aai/scripts/close-reconcile.mjs --check --range A..B --root <toplevel>` → rc 0/1/2 → verdict per `close_gate` read from `git show <local sha>:docs/ai/docs-audit.yaml`.
- close-reconcile `--apply` → `attributionFor(rel)` → `parsePrNumber(commits, grammarsFor(platform))` → `close-work-item.mjs --pr <n>` child process (unchanged).
- doctor → CAT-18 table → `git rev-parse --git-path hooks/<name>` → marker + mode bits → PASS/WARN.

Seams this change shares with features it does not own (PLANNING principle 2), each with the test that crosses it for real:
- S1 hook → `pre-commit-checks.sh` exit code (TEST-801 stages a real secret; the block must propagate rc=1 into a refused commit — a mocked script would test the mock).
- S2 pre-push → close-reconcile range grammar: the hook hands sha ranges that close-reconcile's `resolveRange` must accept (TEST-805/806 push real branches to a real bare origin and read close-reconcile's own OPEN/CLEAN lines).
- S3 close-reconcile → `pr-platform.mjs` classification (TEST-810 detects azure from a real `origin` URL, not a stubbed classifier).
- S4 CHECK 8 → allocator `--guard` (TEST-808 runs the real allocator over a real committed draft; M4's four seconds are part of the suite's cost).
- S5 installer → an existing hook file's bytes (TEST-802 upgrades a real pre-ride body and a hand-merged foreign+marker body and `cmp`s every byte outside the inserted block).
- S6 doctor ↔ installer marker literals (TEST-812's PASS state is produced by running the REAL installer into the fixture, so a drifted literal on either side reddens it).
- S7 pushed-commit config vs worktree config (TEST-816).
- A seam no automated test crosses: a server-side PR merge on GitHub or Azure never runs the pre-push hook; the trigger for that event is CI, which this ride does not vendor (D5) — Residual risk R1.

Edge cases:
- `core.hooksPath` set (TEST-812 and the installer's existing `resolve_hook_path`); linked worktree (existing resolver).
- Push of several refs in one command (one range per line, each verdict independent; the hook exits 1 if ANY default-branch line was refused under enforce).
- Force push to the default branch: `<remote sha>` may be unreachable locally → close-reconcile exit 2 → NOTE under report-only, refusal under enforce (D1).
- A pre-commit hook file without a shebang: the block is inserted at line 1 and a shebang is NOT added (the file's execution semantics are the owner's).
- CRLF hook file: insertion preserves the file's existing line endings for the bytes it does not own; the inserted block uses LF (bash tolerates LF inside a CRLF file only when the shebang line is LF-terminated — the installer refuses to upgrade a file whose FIRST line ends in CR, naming it, rather than produce a hook `sh` cannot start).
- Inverted markers (END above BEGIN), a stray END with no BEGIN, more than one BEGIN or END: refused by name before any write, file byte-identical (D6). A UTF-8 BOM: refused by name. A UTF-16 file: no marker byte sequence on disk, so it is foreign (refused, byte-identical) in both twins — the `.ps1` no longer decodes it into ownership.
- Refresh of an owned block whose file carries a raw non-UTF-8 byte outside the block, or a final line with no trailing newline: both survive byte-for-byte in both twins (D6).
- `node` absent at push (NOTE, exit 0); absent at commit (the INDEX body already exits 0 silently; the guard block prints its NOTE first).

Residual risks:
- R1. A server-side merge is unobservable locally; merge-time detection needs project-owned CI (D5). The intake's downstream case (a PR merged without /aai-pr on Azure) is caught at the LAST PUSH before that merge, as a report, and by nothing after it unless the project wires the documented CI command.
- R2. The Azure grammar is verified against the literal `Merged PR <n>: <title>` form only, from the reporter's data; a live Azure round-trip is fu-azure-live-proof-on-adoption.
- R3. The `.ps1` twin's behavioural arms run only where `pwsh` exists (the CI Windows legs); on a macOS/Linux host without pwsh the static arms alone pass (the same limitation fu-test641-passes-without-pwsh records). TEST-809's pwsh arm sets `refs/remotes/origin/HEAD` and asserts the fallback NOTE does NOT fire, so its recorded mutation (renaming the ref the `.ps1` reads) reddens behaviourally as well as statically where pwsh exists (validation round 1 NB4).
- R4. CAT-18 is a static wiring check (marker + mode bits), not a behavioural probe; a hook that carries the marker but whose interior was edited into a no-op reads PASS. CAT-12/CAT-17/CAT-18 still test the marker as a substring (`includes`), unlike the installer's line-opening rule: they report and never write, so a merely-mentioned marker yields at worst a misleading PASS line there, never a rewrite or a deletion.
- R6. TEST-814's recorded mutation reddens its `--help` arm only; the USER_GUIDE and CHANGELOG arms are green-only assertions, because a v1 mutation record carries ONE target and those files are not the installer (validation round 1 NB5). Named, not fixed.
- R5. Every existing downstream commit path gets ~4 s slower and secrets detection starts refusing commits; both are disclosed (D2, Spec-AC-11) and neither is dialled off by config — a project that wants the old behaviour runs `--uninstall --hooks index` and loses index regeneration with it. Deliberate: a dial that silently disables the backstop is the defect this ride fixes.

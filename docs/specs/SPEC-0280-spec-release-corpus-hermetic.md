     - (c) Overlay with the existing `release-dry-run.mjs` `snapshot()` semantics, and without its final `commit()`.
       - The file set is every path from `git -C <W> ls-files --cached --others --exclude-standard -z`.
       - A listed path that is absent in W is removed from S.
       - A symlink is recreated with the same `readlink` target.
       - A regular file is copied, then chmod-ed to W's lstat permission bits.
       - Ancestor handling follows `destination()`: a symlinked or non-directory ancestor in S is replaced by a real directory.
       - Do not run `git add` or `git commit` in S. Its HEAD and index stay at the branch HEAD, and its working tree carries exactly the candidate delta. That includes the in-scope untracked docs and the modified append-only ledgers. Gitignored runtime files (briefs, reports, tdd, STATE) are excluded, as they are from the executor's own snapshot.
     - (d) Equivalence proof. A scratch node script outside both trees, under /private/tmp/release-corpus-hermetic-scratch/, reproduces `sourceProof()`'s `treeSha256` for W and S.
       - Algorithm: the sorted file set from the same `ls-files` call; for each file, `path` plus NUL, `String(lstat.mode)`, then the readlink target or the file bytes, or `MISSING` for a listed path that is absent; one SHA-256 over all of it.
       - The script also writes a per-path manifest (path, mode, kind, sha256 of content) to `manifest-W.tsv` and `manifest-S.tsv`.
       - PASS requires the two manifests to be byte-identical and the two treeSha256 values to be equal.
       - It also requires these identity facts: `git -C <S> rev-parse HEAD` equals `git -C <W> rev-parse HEAD`; `git -C <S> rev-parse --absolute-git-dir` and `--git-common-dir` both resolve inside S (an independent .git); and `git -C <S> worktree list` names only S.

## Scope and design

### D1 Registry

`.aai/system/HARNESS_SKILLS.yaml` gains a `shims:` section (same line discipline as `trees:`), one row per
generated file: `<path>|<fragments>|<name>|<cli>`. `<fragments>` is a `+`-joined ordered list of fragment
ids; `<name>` and `<cli>` are the values of the only two placeholders (`-` when the fragments use none).
The fragment text lives in `.aai/system/HARNESS_SHIMS.md`: a fragment starts at a line that is exactly
`<!-- fragment: <id> -->` (id `[a-z0-9-]+`); its text is every byte after that line up to the next fragment
line or end of file. Bytes before the first fragment line are a header and are ignored. Output of a row =
its fragments concatenated in order, with `{{name}}` and `{{cli}}` replaced. This keeps one registry for
harness adapters (RFC-0017 §4) and puts human-edited prose in a Markdown file.

When the `shims:` section is present it must hold exactly these six paths, each once: `CLAUDE.md`,
`AGENTS.md`, `CODEX.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursor/rules/aai.mdc`
(the allowed set is hardcoded in `lib/harness-shims.mjs`, as REQUIRED_MIRROR_TREES is for trees). When the
section is absent (existing test fixtures pass their own `--manifest` without it) no shim is generated or
checked and `--check` prints `SHIMS: none declared`.

Exit 2, naming the cause: a placeholder other than the two, a fragment id a row names that the file does
not define, a fragment the file defines that no row names, a duplicate fragment id, a malformed row, a
duplicate path, a path outside the six, or a present section missing one of the six.

### D3 Generator and gate

`.aai/scripts/lib/harness-shims.mjs` (new) parses the section and the fragment file and renders the six
outputs. `sync-harness-skills.mjs` calls it in both modes, after the tree work:

- `--check` compares, for each declared path, the bytes on disk under `--root` with the rendered bytes, and
  compares the normalized hash (D4) of the rendered Copilot shim with the rows of
  `.aai/system/COPILOT_SHIM_SHIPPED.list`. Each differing or absent path prints one line
  `DIVERGE shim <path>: <first differing line or absent>`; an unrecorded Copilot hash prints
  `DIVERGE shim .github/copilot-instructions.md: unrecorded <hash>`. Any such line, or any tree divergence,
  exits 1. When nothing differs it prints the existing tree OK line unchanged and then
  `OK: 6 shim(s) match the registry`, exit 0.
- `--write` writes every differing or absent path with the rendered bytes, appends the rendered Copilot
  hash to the shipped list when it is not there, and prints one `WROTE` summary line covering trees and
  shims. A second `--write` changes nothing.

Line caps: `lib/harness-shims.mjs` at or under 260 lines; `sync-harness-skills.mjs` at or under 590 (538 today).

### D4 Copilot shipped versions and the sync merge branch

`COPILOT_SHIM_SHIPPED.list` holds one lowercase 64-hex sha256 per line (`#` comments and blank lines
ignored). Each is the hash of N(text), where N deletes every CR and then the trailing LF characters. It is
seeded with N-hashes of every distinct historical blob of `.github/copilot-instructions.md` reachable from
`ff32ec2e` (9 blobs but 8 distinct hashes today, because two historical blobs differ only in CR characters) and gains the new rendered version through `--write` (9 rows after this scope).

In `aai-sync.sh` (function `copilot_shim_is_shipped`) and `aai-sync.ps1` (function
`Test-CopilotShimShipped`): after the existing override extraction (including the existing fallback to the
override file when the extraction is empty), when the override text is empty or its N-hash is a row of the
source's list, the target shim is replaced by the source shim (`copy_replace` and its PowerShell twin), no
`Project Overrides (auto-merged)` block is written and the override file is neither written nor removed.
Otherwise the existing merge branch runs unchanged. When no hash tool works (bash tries `sha256sum`, then
`shasum -a 256`; an output that is not 64 hex counts as failure) the text counts as not shipped, so the
existing merge keeps it.

### D5 Root AGENTS.md is installed, not deleted

Both sync twins drop `AGENTS.md` from the legacy root deletion loop (PLAYBOOK.md stays in it) and add it
to the root shim loop that already carries CLAUDE.md, CODEX.md, GEMINI.md and SKILLS.md, so a target's own
differing `AGENTS.md` is replaced and named in the sync conflict advisory, the same policy as CLAUDE.md.
A fresh target receives all six shims byte-equal to the source, and
`node <target>/.aai/scripts/sync-harness-skills.mjs --check --root <target>` exits 0 there.

## Risks and rollback

- The `--check` gate compares the bytes of each declared path with the rendered registry output and the
  rendered Copilot hash with the shipped list. It does not judge whether the text is right for the harness
  that reads it.
- The sync rule (D4) compares the N-hash of the extracted override text with the list. A downstream whose
  override block holds an older shim with any byte changed is treated as a real override, as today.
- The AGENTS.md change (D5) replaces a downstream project's own differing `AGENTS.md` and names it in the
  conflict advisory (the CLAUDE.md policy); before, it was deleted without a mention. Git is the backup in
  both cases.
- Rollback: revert the PR. The shipped list and fragment file are inert for the old generator and old sync;
  the ledger lines stay (append-only) and stay true.

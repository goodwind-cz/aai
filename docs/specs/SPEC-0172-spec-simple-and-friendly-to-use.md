## Design decisions
- **D1 — the golden flow is the DETERMINISTIC ride, driven by one script.** `golden-flow.mjs` builds a fresh downstream target the way the self-hosting smoke does, adds a git origin (bare, `HEAD -> refs/heads/main`), then runs the ride's own CLIs in the order the skills call them: intake doc from the template, spec draft, `spec-freeze.mjs`, a delivery commit on a ride branch, a merge into `main`, `close-work-item.mjs`, `docs-audit.mjs --check --strict`, then the gate of D2. It runs every step with stdin closed and a 120 s timeout per step, so a step that waits for a human is observed, not hung. Everything an LLM turn would add (wording, an extra question) is outside this script; that residual is written down under Constraints.
- **D2 — "nothing left behind" is one command with four named classes.** `nothing-left-behind.mjs --ref <slug>` composes what already decides each half: `git status --porcelain` (files), `docs-audit.mjs --check --strict` (docs), the ride's own intake doc and spec frontmatter `status` (drafts for shipped work), and `follow-ups.mjs list --json` filtered to `ref_id == <slug>` whose follow-up `id` begins with one of a closed list of ceremony-subject prefixes (registry). It exits 0 only when all four are empty, else 1 and names every item under its class, and `--json` returns the four counts. AMENDED 2026-09-07 (owner-signed, `spec-amend`): the registry class was decided by a six-word match on the `finding` TEXT, which counted any item that MENTIONED the ceremony rather than any item that WAS about it — a follow-up describing a defect IN this gate necessarily uses the word ceremony, so the gate stopped the ride for naming its own weakness. The class is now decided from the structured `id` prefix and never from prose: a genuine ceremony-incomplete item is filed under a ceremony subject and still counts, while an item whose subject is the delivered gate (`fu-gate-*`) or an owner sign-off owed by design (`fu-amend-*`, SPEC-0165) is excluded STRUCTURALLY rather than by wording.
- **D3 — the record is an append-only line, and the diff is a command.** `docs/ai/tests/golden-flow.jsonl` gains one JSON line per run (`docs/ai/tests` is already a canonical `docs/ai` child; the file is tracked, not ignored). `golden-flow.mjs --diff` compares the last two lines field by field and exits 1 when any count rose. "Behaves worse than before" is that exit code.
- **D4 — per release means the release dry run NAMES a missing record; it does not block.** `aai-release.sh --dry-run` lists under `## Preconditions` when the newest record's `run_utc` is older than the previous tag's commit date, in the same NAMED-not-blocking style as the unlogged-PR check (SPEC-0170 D2). Bash only; `aai-release.ps1` parity is a residual named under Constraints.
- **D5 — CI proportional to the change is a map fix, not a workflow rewrite.** The two unmapped paths, plus the whole `docs/ai/tests/**` family, are mapped in `tests/skills/suite-map.yaml` to the suites that read them (`aai-metrics` and the framework suites for `test-runs.jsonl`; `aai-release` and `aai-update` for `AAI_VERSION.md`), so `select-suites.mjs` never escalates a docs-or-ledger-only diff. The workflow file is untouched.
- **D6 — the maintenance half owns the merge-time trigger.** This spec makes the gate route-independent and runs it in the golden flow and in `SKILL_PR` before the push. Firing it at the merge event for a PR opened by any route is `close-ceremony-fires-only-via-aai-pr`, the paired maintenance ride, which will call `nothing-left-behind.mjs` rather than re-derive its checks.
